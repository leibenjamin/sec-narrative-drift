# Demo Readiness

## One-sentence product description
Document Protocol Lab is a bounded SEC Item 1A pilot that shows how an evidence-first document workflow answers first, explains protocol meaning second, and keeps deeper audit third across NVDA, LLY, and KO.

## Recommended first-click path
- Start on Home and open `NVDA`.
- Use Cases only when you want to choose the role deliberately instead of taking the default strongest first signal.

## What each fixture demonstrates
- `NVDA` shows the strongest first signal: a vivid filing shift where the answer-first pattern becomes legible immediately.
- `LLY` shows the policy-heavy bounded contrast: pricing, reimbursement, concentration, and access pressure without pretending the full lower-audit runtime stack is public for that issuer.
- `KO` shows the restraint / low-drift honesty check: the workflow stays useful even when the filing is mostly stable and the right read is selective sharpening rather than drama.

## How to explain bounded LLY honestly
- Describe `LLY` as a bounded visible case, not as a full lower-runtime integration.
- The public slice includes the filing answer, protocol meaning, Fresh vs reused, and the matched-effort integrity surface.
- The stop is intentional. It prevents the page from implying more audit depth than this issuer currently exposes on the public surface.

## How to explain evidence and audit layers
- The first layer is the filing answer with nearby filing evidence.
- The second layer is protocol meaning: why this fixture is in the lab and what the comparison geometry adds.
- The third layer is deeper audit and provenance for readers who want methods, agreement, structure, or compare details.
- Optional or missing artifacts stay explicit instead of silently falling back.

## How to explain the static runtime
- Static JSON only at runtime.
- Everything in the shipped app is loaded from static JSON under `public/data/...`.
- There are no runtime LLM or ML calls in the shipped product.
- Model outputs, when present, are offline sidecars with explicit provenance and deterministic runtime projection.
- SEC text is treated as untrusted and rendered as plain text only.

## What not to overclaim
- Do not describe the product as a broad issuer gallery, benchmark suite, or whole-filing research platform.
- Do not imply that `LLY` exposes the same lower-audit runtime depth as `NVDA` or `KO`.
- Do not describe backstage registry coverage as the public case list.
- Do not describe Fresh vs reused as an equal top-level read; it remains a bounded secondary lens.
